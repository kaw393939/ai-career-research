# Decode the job description

These are short editorial explanations for reading the role profiles. Different employers may use the same term differently. For role-specific evidence, follow the profile links.

## Agent

A system in which a model can choose actions or tools to work toward a task. A useful job-description question is: what can it do, under whose permission, and how is its behavior tested?

## AI engineer

Often an engineer who builds software using AI capabilities. The title can also describe customer-facing implementation or broader ML work. [Read the profile](../roles/ai-engineer).

## AI forward engineer

An ambiguous phrase. It may mean a **forward-deployed engineer**, but check the actual responsibilities rather than assuming it is a standardized title. [Read the profile](../roles/forward-deployed-engineer).

## Baseline

A reference approach you compare against, such as keyword search, a simple model, or the previous system version. A more complex system should demonstrate why it helps.

## Evaluation / evals

A repeatable way to measure system behavior against defined tasks and criteria. It may combine automated checks, human judgments, and error analysis. [Explore evaluation work](../roles/ai-evaluation-engineer).

## Fine-tuning

Additional training that updates a model's parameters using a selected dataset. It differs from changing a prompt or supplying documents at request time.

## Forward-deployed engineering

Engineering embedded close to customers or end users, usually combining problem discovery, software development, integration, and delivery. It is not necessarily an AI-specific role. [Read the profile](../roles/forward-deployed-engineer).

## Grounding and citations

Grounding connects an answer to supplied or retrieved information. A citation points to supporting evidence; its presence alone does not prove the answer is correct or supported.

## Inference / model serving

Inference is running a trained model on an input. Serving is the system that makes that capability available, with concerns such as availability, latency, capacity, and cost.

## Large language model / LLM

A model trained to work with language and related sequences. In an application, its output still needs task-appropriate validation. [Explore LLM engineering](../roles/llm-engineer).

## Machine learning operations / MLOps

Practices and infrastructure for building, deploying, monitoring, and updating ML systems. The operational work overlaps with several engineering titles. [Explore ML engineering](../roles/ml-engineer).

## Prompt engineering

Designing instructions, examples, and input structure to guide a model's behavior. It can be one responsibility within a broader role; the phrase alone does not establish a distinct or stable career path.

## Retrieval-augmented generation / RAG

Retrieving relevant information and providing it to a model as context for generating an answer. Retrieval quality, permissions, citation support, and appropriate abstention all need attention.

## Solutions architect

A role that connects organizational needs to system design and technical tradeoffs. In AI, this can include model selection, data flow, security, evaluation, and operation. [Read the profile](../roles/ai-solutions-architect).

## Tool use

A model-driven application requesting an external operation, such as querying a database or calling an API. The surrounding software controls permissions, validates inputs, handles errors, and decides what can execute.
