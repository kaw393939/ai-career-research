# Forward-Deployed Engineer

A forward-deployed engineer works with customers to turn operational problems into deployed software, sometimes including AI.

**Classification:** Established role with AI responsibilities · **Foundations:** Full-stack development, Delivery · **Focus:** customer delivery

**Also search:** FDE, FDSE, forward-deployed software engineer

<span id="how-this-role-is-changing"></span>
<span id="what-the-work-looks-like"></span>

## What you do

Combine customer discovery, code, data integration, architecture and deployment ownership. Communicate with users, engineers and executives; ask whether the team owns pilots, sales support, long-term maintenance or all three. Models and agents add new deployment work, but FDE is not inherently AI-only.

<span id="skills-to-practice"></span>

## Skills

- Discovery: turn user interviews into a testable problem.
- Software and data: working integrations, interfaces and documented data flow.
- AI delivery: evaluate outputs and handle uncertainty.
- Communication: demos, decisions and understandable status updates.
- Operations: handover, failure scenarios and rollback.

<span id="entry-routes-and-title-boundaries"></span>

## Example requirements

**Palantir — Forward Deployed Software Engineer:** hands-on discovery, applications, data, architecture and deployment in its customer/platform environment; the sampled role asks for **at least one relevant post-college year**. Its early-talent resources describe FDSE and software-engineering pathways; check current cohort eligibility.

**Anthropic — Forward Deployed Engineer, Munich:** production AI applications, deployment support and reusable patterns for product teams; the example asks for **8+ years**, substantial travel and language requirements. These conditions belong to that posting.

“AI forward engineer” is not a standardized equivalent. Software engineering, data integration and technical consulting offer related practice; the actual description determines whether a role involves AI.

<span id="portfolio-project-an-embedded-delivery-case-study"></span>

## One project

**Embedded delivery case study.** Build a bounded request-routing workflow with a student organization, nonprofit or small business, using synthetic or approved public data.

1. Write a one-page user/problem brief with constraints and a success measure; record a baseline, separating estimates from measurements.
2. Deliver an end-to-end application and demonstrate human review for uncertain or consequential decisions.
3. Test **20 realistic cases**, including missing data and failed dependencies.
4. Publish a handover guide, unresolved failures and feedback from **one user session**.

Without a partner, label the customer and feedback as simulated; never report invented interviews or hypothetical improvements as observations.
