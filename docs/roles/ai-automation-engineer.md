# AI Agents & Automation Engineer

**AI agents and automation engineering** is an editorial focus category for software that connects models, tools, and business workflows. Employers may call this applied AI, AI software engineering, agent engineering, or automation development. The category is not proof of a standardized new title or a separate entry-level profession.

## How this role is changing

**Editorial classification: Overlapping employer title.** Probabilistic tool selection adds permission and evaluation concerns. Traditional foundations: Process analysis, Backend development. This is a responsibility-based interpretation of the employer evidence below, not a claim that a title is newly invented.

## What the work means

Bitdeer's **2027 US AI Engineering – New College Graduate** includes agent-platform capabilities such as tool integration and workflow orchestration among several possible tracks. C3 AI's **Forward Deployed Engineer – Federal, New Grad 2027** combines enterprise AI application delivery, debugging, customer demonstrations, and training; its skill areas include LLM tool calling. These show overlap between agent work, application engineering, and customer delivery. [Bitdeer description](https://bitdeer.breezy.hr/p/826249d5dbdc-2027-us-ai-engineering-new-college-graduate) · [C3 AI description](https://c3.ai/job-description?gh_jid=8900477002)

MANTECH uses the exact title **Automation AI Developer** for enterprise agents, prompts, workflow implementation, testing, stakeholder demonstrations, and release documentation. Its description explicitly concerns a **future opportunity**. It is useful evidence of work requirements, with **status uncertain**, rather than a confirmed immediate opening. [MANTECH description](https://careers.mantech.com/en_US/careers/JobDetail/Automation-AI-Developer/66187)

## Skills to investigate

Investigate programming, APIs, process analysis, integration testing, model-output evaluation, and technical communication. A useful system must handle errors and uncertain responses as well as successful demonstrations.

Preserve required/preferred distinctions. For example, MANTECH requires relevant development and enterprise agent or LLM-workflow experience; Python, REST, vector databases, and RAG appear in preferred qualifications. A summary of every mentioned tool would overstate its mandatory requirements. [MANTECH qualifications](https://careers.mantech.com/en_US/careers/JobDetail/Automation-AI-Developer/66187)

## Compare the career stages

- **Internship:** T-Mobile's **Summer 2027 Assoc AI Engineer Internship** offers mentored work on AI-driven decision workflows and accepts foundational coursework or project evidence. It requires continuing enrollment, age 18+, and US work authorization. It is a broad applied-AI example, not an agent-specific guarantee. [T-Mobile description](https://careers.t-mobile.com/summer-2027-assoc-ai-engineer-internship/job/41098459CF0B94062E8E6D1939C8EE38)
- **New graduate:** C3 AI identifies graduation windows and customer delivery alongside senior engineers. Its federal example also requires US citizenship, clearance eligibility, and on-site attendance; Bitdeer's program has different eligibility and assignment conditions.
- **Experienced:** MANTECH requests 3+ years of relevant development, US citizenship, and Public Trust. Remote work can include client travel. A public project does not replace those conditions.

## Portfolio practice: an auditable workflow

This is editorial guidance. Build a clearly labeled simulated request-routing workflow using synthetic records. Define a 20-case test set before implementation. Show a successful tool call, malformed input, a failed dependency, and an uncertain result routed for human review. Publish the scoring rubric, observed failures, release notes, and a short user guide.

Explain which actions require approval and what the system actually executes. Separate simulated outcomes from observed results.
