# v1.1 plan: broader technology careers

**Status:** Shipped · **Created:** November 5, 2026 · **Findings:** REV-01, REV-02, REV-03

**Source:** [GitHub issue #1 — not enough other fields](https://github.com/kaw393939/ai-career-research/issues/1), currently open when this plan was written. The issue identifies missing security, networking, and wider technology-industry coverage.

## Problem and intended result

The site emphasizes building and deploying AI software. A student interested in protecting systems, connecting networks, or operating technology should also be able to investigate how AI changes that work.

Organize discovery around technology fields and responsibilities. Keep the AI Career Atlas name while broadening its framing to AI's transformation of technology careers.

## Research and content work

1. Start with **cybersecurity** and **networking/telecommunications**. Investigate employer usage of terms such as AI security, AI red teaming, security automation, network automation, and network AI/ML. These are search leads, not verified new occupations.
2. Extend coverage to cloud/IT operations, data engineering, quality/testing, and embedded systems/robotics where primary evidence supports useful profiles.
3. For each example, identify whether it represents an AI-specific specialty, an established role with changed responsibilities, or a different label for similar work. Explain uncertainty and overlap.
4. Describe traditional foundations, AI-related changes, actual deliverables, and a student portfolio suggestion. Preserve exact employer titles in the evidence library.
5. Unify the original and additional role profiles in one discovery structure, with field and work-interest filters. Keep internships and entry-level examples first.

## First milestone

Aim for **4–6 verified US employer examples across security and networking**, from multiple employers, with early-career examples where they can actually be found. Report gaps rather than inventing junior versions of senior work. Add other domains in documented increments.

## Acceptance criteria

- [x] Security and networking each have a sourced comparison/profile explaining concrete AI-related responsibilities.
- [x] Each included example has a direct employer source, review date, location, eligibility, stage rationale, and availability label.
- [x] Required skills remain separate from preferred skills and editorial portfolio ideas.
- [x] Every profile clearly distinguishes evidence of changed work from claims that a title is new.
- [x] All existing profiles remain discoverable through the unified structure.
- [x] A student can start from a work interest, reach a profile, and inspect an employer example.
- [x] Build/link checks, desktop/mobile navigation checks, and deployed-page verification pass.

## Boundaries and risks

Avoid title inflation, unsupported hiring-growth claims, and duplicated profiles that differ only in wording. NIST/CISA and other technical standards can explain responsibilities; they do not prove demand for a title. Do not close issue #1 until the implemented coverage is reviewed against its concern.
